# Laertius - Architecture Reference

Per-layer judgment calls, accepted risks, and deliberately unmapped names. Read the module header before editing any layer. Volatile counts below (claim totals, tag counts, etc.) are indicative; the registered validators are the source of truth.

## Retrieval

- **Runs fully free / no API key by default**: local embeddings; Ask works without any LLM (extractive key-findings summary). **Optional generative RAG** (`generate-answer.ts`): when an OpenAI-compatible endpoint is configured (`LAERTIUS_LLM_BASE_URL`/`_API_KEY`/`_MODEL`, falling back to `OPENAI_*`), Ask synthesizes a cited answer from the retrieved passages and answer cards; unconfigured or failing LLM falls back to the extractive summary (pinned by `validate-ask-generative`). **No database** - corpus and indexes are files, portable to any Node host
- **Retrieval** (`corpus.ts`, `bm25.ts`, `dense.ts`, `rag.ts`): BM25 (Greek normalization: lowercase, strip diacritics, fold final sigma) + dense cosine + RRF (k=60, pool=50); both channels index Greek + English concatenated, so English queries work everywhere; E5 requires `query: ` / `passage: ` prefixes

## Knowledge Graph

- **Knowledge graph** (`kg.ts`): ~80 curated cited edges; nodes derived from the corpus at runtime, so dangling edges are impossible; hybrid search boosts philosophers detected in the query + graph neighbours

## Claims

- **Claims** (`kg-claims.ts` + `claims/book*.ts`): 1564, cited, certainty model asserted/reported/disputed/conjectured, `conflictsWith` between rival reports; all with verbatim Greek excerpts validated against the cited section. Object properties never carry literals. When D.L. records a transmission chain ("Sosicrates, who quotes Hermippus"; "Heraclides in his epitome of Satyrus/Sotion"), the claim carries `chain` (nearest intermediary first, `accordingTo` is the source closest to D.L.), emitted in LOD as `lo:transmissionChain` -> `lo:ChainLink` nodes; a chain authority must be some claim's accordingTo, a SOURCE_WORKS author, or a corpus philosopher (the last hop of a chain can be a philosopher's own remark: Favorinus <- Hermippus <- Arcesilaus of Pitane at 5.41, the longest chain in the work; the philosopher-as-authority gets a separate lo:Source node under the source/philosopher double-node convention, and its shared name is suppressed from gazetteer auto-surfaces in both languages so the philosopher keeps the text tags), and chain authorities always mint source nodes. In LOD only *asserted* claims become direct triples; hedged ones exist only as `lo:Claim` reifications

## Verses

- **Verses** (`verses.ts` + `verse-authors.ts`): 340 from TEI block-quotes; 233 curated poet attributions - only where the text names the poet - yielding `lo:Verse` nodes

## Sayings

- **Sayings** (`sayings.ts` + `sayings/book*.ts`): 637 / 50 philosophers, hand-curated TS - deliberately not auto-detected, extraction can't tell speaker from subject. Controlled topic union, verbatim `en`+`grc` enforced (section owner must match unless `crossAttributed`; `grcRef`/`toRef` overrides). `lo:Saying` reifications; asserted ones also get direct `lo:said`. Addressees (92) mint NO new nodes; `accordingTo` authorities (33) DO mint `lo:Source` nodes, which auto-feed the tagging layers

## Testaments

- **Testaments** (`epistles.ts`): 6 wills quoted verbatim - Plato 3.41-43, Aristotle 5.11-16, Theophrastus 5.51-57, Strato 5.61-64, Lyco 5.69-74, Epicurus 10.16-21; D.L. is the sole surviving source for all. Beneficiaries/executors/witnesses are ALWAYS literals; only `involves` links existing corpus philosophers (the four successor links); NO authenticity field, NO `accordingTo` (Ariston of Ceos stays in `note` - avoids minting a source node). `lo:Testament` DOCUMENT nodes; each will spans multiple sections, and per-section LOD seeds the will from its full section span (`dcterms:source` points to the opening section)

## Doxai

- **Doxai** (`doxai.ts` + `doxai/book*.ts`): 169 / 33 philosophers, hand-curated TS - the doctrinal tenets D.L. reports, 12-domain locked union distinct from saying/anecdote topics; verbatim Hicks `en` enforced, Greek where curated with `grcRef` for section-boundary drift; mints NOTHING: `doctrine` links only existing doctrine nodes, `accordingTo` only existing authorities, rival attributions stay literals; may not normalized-EQUAL a saying. `lo:Doxa` DOCUMENT nodes with `lo:heldBy`/`lo:expressesDoctrine`. **Owner-aware ref resolution** (`doxaSectionIdFor`): bare Hicks refs are ambiguous where numbering restarts across chapters (7.160 Zeno/Ariston, 7.166 Herillus/Dionysius) - the section owned by the doxa's philosopher wins, else first-match; the validator, API serialization, and LOD all resolve through it; claims resolve the same way (`sectionIdForRef(ref, subject)` in `claims-answer.ts` prefers the section owned by the claim's subject, so e.g. the three-way 2.124 Simon/Glaucon/Simmias split resolves per claim)

## School Memberships

- **School memberships** (`school-members.ts`): cited school rosters, 34 members: 8 Epicureans of the Garden, 23 Sceptics (Pyrrho's pupils 9.68-69, Timon's pupils 9.114-115, the chain down to Saturninus 9.116, the criterion men Theodosius/Apellas), 3 later Academy scholarchs (Telecles, Evander, Hegesinus, 4.60). Every entry gets a reified `rdf:Statement` with the D.L. citation; only `asserted` entries also get the direct `lo:memberOf` triple (hedged: Timocrates the renegade brother, since a bare source node would conflate him with the Dion author at 7.2; Theodosius, who denied the Pyrrhonean label; Nicolochus and Praÿlus, who hang on the disputed 9.115 list). Members may be person OR source nodes; the source pool is the base graph's authorities (claim, saying and anecdote sources plus the minted authorities source-mentions opts into tagging), so memberships can never point at sourcesIndex-only nodes. `lo:memberOf` domain is `foaf:Person`. Competency question `garden-members` (17 total) checks the roster via SPARQL

## Succession Links

- **Succession links** (`succession-links.ts`): 25 cited teacher-pupil links whose endpoints are not both chapter subjects (Pyrrho's pupils, Timon's pupils, the unbroken 9.116 chain Euphranor -> ... -> Saturninus, the Academy handover Lacydes -> Telecles/Evander -> Hegesinus -> Carneades). Mints NOTHING: endpoints must be existing philosopher/person/source nodes, lod.ts throws otherwise. Asserted links get the direct `lo:teacherOf` plus a reification; the hedged Hippobotus/Sotion pupil list (9.115) is reification-only, opposed by Menodotus' report that Timon left no successor (the dispute lives in claims/book9.ts). `lo:teacherOf`/`lo:studentOf` domains widened to `foaf:Person` for this layer

## Person Mentions

- **Person mentions** (`person-mentions.ts`): curated mention-persons (Sceptics of 9.68-116, Academy scholarchs of 4.60, and frequently-mentioned figures like Isocrates, Dion of Syracuse, Asclepiades of Phlius, Aristocreon with no Life of their own) minted as `lo:Person` nodes with verified QIDs where they exist; they auto-feed the tagging layers like other person nodes. Ambiguous bare names (Dion, Asclepiades) are scoped via `onlySections` on BOTH the MentionPerson entry (English) and the GreekNameSpec (Greek)

## Epistles and Anecdotes

- **Epistles** (`epistles.ts`): 31 letters; authenticity verdict authentic/disputed/spurious = 3/8/20. `lo:Epistle` DOCUMENT nodes; sender/addressee link only to existing nodes, else literals
- **Anecdotes** (`anecdotes.ts` + `anecdotes/book*.ts`): 334 / 67 philosophers; locked 14-topic union; may CONTAIN a saying's text but never normalized-EQUAL it; `involves` (154) and `framesSaying` (63) links mint nothing. `lo:Anecdote` DOCUMENT nodes; participants link only to existing nodes, else literals

## Source Works and Person Works

- **Source works / person works** (`source-works.ts`, `person-works.ts`): works cited *as sources* emitted as `lo:Work` + `lo:wrote` from existing nodes; lod.ts throws on dangling references or double-minting. Greek titles in `GREEK_WORK_TITLES` feed both LOD and the tagger; new eponymous single-word titles must be checked against the text before allowlisting

## Text Tagging

- **Text tagging** (`gazetteer.ts`, `annotate.ts`, `greek-names.ts`): deterministic, no LLM - 8712 occurrence-level tags across 762 entities, pinned by `validate-annotations`. Longest-match-first with word boundaries; scoped (curator-verified) entries outrank unscoped ones and the section-owner heuristic; ambiguous bare names (Zeno, Diogenes, ...) tag only via the section-owner heuristic in BOTH languages; occurrence-level homonym splits (Apollodorus, Antigonus of Carystus) are hand-classified per section. Greek names: ~1400 curated declined forms; a match requires the ORIGINAL token capitalized; unresolvable homonyms in `GREEK_NAME_SKIPS` (pinned). **The gazetteer builds from `graphAsTurtle({ sourcesIndex: false })`** - the bibliographic index is full of bare homonyms and must never feed tagging

## LOD Exports

- **LOD exports** (`lod.ts`): `/api/lod/graph.{jsonld,ttl,rdf}`, `graph-annotated.*` (graph + passages + all stand-off `oa:Annotation` tags, ~190k triples, cached), `ontology.{ttl,rdf}`, per-section `/api/lod/section/:id.{jsonld,rdf}` (one-hop subgraph + `lo:Passage` + tag annotations). RDF/XML is derived from the Turtle so serializations can never drift. Includes Roche's OTV ontoterminology layer with the full double dimension: every named node (incl. all 847 works) gets `otv:ProperName` linguistic nodes (`/name/...`) linked via `otv:denotedByProperName`, one node per language (English keyed by the label slug, Greek keyed by the Greek string's slug, both carrying plain xsd:string literals with `otv:language` naming the language: the OTV core declares `otv:properName` range xsd:string, so lang-tagged literals or mixed-language nodes would be OWL-inconsistent; entities link to BOTH their English and Greek nodes and the validator enforces bidirectionality); name tags in the oa: layer carry TWO `oa:hasBody` values (conceptual node + ProperName); term tags body the `otv:Term` plus every doctrine `otv:Concept` it denotes (terms without a doctrine keep the single linguistic body); the six closed vocabularies (51 individuals) are typed `otv:Concept`; no `owl:imports` - the ontology mirrors the OTV core skeleton it uses. Work ProperNames feed annotation bodies only - the gazetteer excludes kind=work from ProperName-driven surface generation (both languages) so work tagging stays label-driven and pins don't move. Counts/subsets pinned by `validate-lod`. Base URI defaults to `https://humanisticadigitalia.eu/Laertius` (`LOD_BASE_URI` overrides) — deliberately the legacy path-based address, NOT the live subdomain: LOD identifiers are stable, so they stayed put when the site moved to `https://laertius.humanisticadigitalia.eu`; the IONOS smoke test pins the base and `check-live-ionos` probes that legacy URIs still dereference (redirect) on the live host

## SPARQL Endpoint

- **SPARQL endpoint** (`routes/sparql.ts`): read-only oxigraph in-memory store lazily loaded from the plain (not annotated) graph to bound memory; GET/POST; SELECT/ASK -> JSON, CONSTRUCT/DESCRIBE -> Turtle; updates rejected

## Terminology Section (OTB export)

- **OTB model + emitter** (`lib/otb/`: `build.ts`, `inventory.ts`, `emit.ts`; routes in `routes/otb.ts` under `/api/otb`): a TEDI 4.1-style ontoterminology export of the corpus, modelled on Maria Papadopoulou's reference export (author: Maria Papadopoulou, publisher: University of Crete) and kept fully separate from the LOD layer (`lod.ts` untouched; different base URI, TEDI's `www.ontologia.fr/OTB/` convention with a dated fragment namespace). Inventory: 9 categories, 21 concepts, 16 relations, 6 attributes, 27 terms, 7589 objects, 1306 proper names (489 Greek), 1563 assertions. Enrichments over the minimal export: every concept carries hand-picked `skos:example` objects (validated to be instances of the concept or a descendant); the curated mention persons and mention places join the object inventory (deduped against philosophers, sources-index persons and coordinate places); and every embedded document (testament, epistle, verse, saying, anecdote, opinion) links via `hasContent` (domain widened to Assertion or Document) to a `txt-<docId>` Text object carrying its verbatim excerpt as language-tagged literals (`xml:lang` grc/en; claim texts tag their Greek too; `cts` anchors stay untagged). The RDF/XML export (`/api/otb/ontoterminology.rdf`, ~6.9 MB, served as an attachment) is emitted directly (not derived from Turtle); `validate-otb` pins the inventory counts, the per-document Text closure and the example closure, and re-parses the full export for well-formedness. A second export, the TEDI-style HTML term dictionary (`lib/otb/dictionary.ts`, served inline at `/api/otb/dictionary.html`, ~2.7 MB), reproduces TEDI 4.1's self-contained "Tedi HTML viewer" page (inline TEDI stylesheet, search box over a term `<select>`, prebuilt per-term entries in a `dictionnaire` JS array) from the same model: all 27 terms (English first, then Greek, each alphabetical), each with its definition, part of speech, status, cross-language equivalents, denoted concept with "a kind of" parent and axiomatized relations (same ancestry filter as `/api/otb/concepts`), and the full roster of direct-instance objects with proper names and allonyms. Output is deterministic (the only date is the pinned `exportDate`), entries are embedded as JSON string literals with `<` escaped so no `</script>` can break the inline script, and the smoke test's OTB drift group requires the served page to be byte-identical to the source emitter (with positive-control fragments first, so the comparison can't pass vacuously). The term dictionary also ships per language, as TEDI writes it: `/api/otb/dictionary.en.html` (English terms only) and `/api/otb/dictionary.grc.html` (Greek terms only), the variants the Terminology pages link; each keeps the other language's "Equivalent" lines inside its entries (as the reference per-language exports do), the title and term count reflect the filtered list, and the smoke test adds a language-purity guard on each option list (no Greek-script term in the en file, only Greek-script terms in the grc file) on top of the same drift contract. The combined `/api/otb/dictionary.html` stays served for continuity. A third export, the TEDI-style HTML proper name dictionary (same emitter file, served inline at `/api/otb/proper-names.html`, ~1.3 MB, modelled on the pn.<lang>.html reference), lists all 1298 proper-name records (English, then French, then Greek, each alphabetical): each entry shows the name, "is a" with the term denoting its object's concept in blue (same language preferred, English fallback, or the italic "there is no term denoting the concept" line), the "allonym(s)" line, then the denoted object with its concept in green, optional Comment, attribute values quoted as &apos;value&apos;, and relations whose targets render as their proper name when one exists, else as &apos; plus the fragment id (the reference's deliberate asymmetry). Allonyms in the model are ids of other proper-name records, never surface strings: both dictionaries must resolve them via the name index before rendering (the smoke test rejects any `_en`/`_grc`/`_fr` id leaking into the option list) and each allonym record is a first-class entry of its own, as in the reference. The same drift contract applies: deterministic output, positive controls, then byte-equality against the source emitter. The proper name dictionary also ships per language, as TEDI's pn.<lang>.html reference does: `/api/otb/proper-names.en.html` (591 names), `/api/otb/proper-names.fr.html` (222) and `/api/otb/proper-names.grc.html` (485), the variants the Terminology pages link; the title reflects the filtered language, entries are unchanged (relation targets still resolve in-language with English fallback), and the smoke test adds the same guards as the per-language term dictionaries plus a partition check (the three files must cover the combined 1298 exactly; Greek-script purity on the grc option list, none in en/fr). The combined `/api/otb/proper-names.html` stays served for continuity. Proper-name entries whose object has a curated Wikimedia Commons depiction (`lib/otb/depictions.ts`, generated offline by `scripts/src/fetch-depictions.ts` from Wikidata P18 over the already-curated QID tables: PHILOSOPHER_META (now complete, all 82 chapter philosophers carry QIDs: Pyrrho Q192313, Herillus Q248975, Clitomachus Q466951 and Glaucon Q1364945, Plato's brother, whose enwiki article records D.L. 2.124's nine dialogues, were the last four), ENTITY_QIDS, PLACE_QIDS, the person-mentions and place-mentions QIDs, and the sources-index authorities; 241 objects, all freely licensed: public domain, CC BY/BY-SA, CC0) render the thumbnail inside the entry with a credit line linking the Commons file page (artist when known, license always); the term dictionary's object rosters render the same thumbnail (smaller, 150px cap, since a roster can list hundreds of objects) via the shared `depictionHtml` helper; the image URL is the Commons `Special:FilePath` thumbnail redirect, so the pages stay self-contained (no bundled binaries) and the smoke test adds an `\u003cimg` positive control to the combined and per-language files of both dictionaries. The depiction table is dictionary/viewer-layer only: it never touches the RDF model, so `validate-otb`'s pins are unaffected, mirroring the `PLACE_COORDS` precedent. A fourth export, the TEDI OTV standalone ontology viewer (`lib/otb/viewer.ts` plus the shell in `viewer-template.ts`, served inline at `/api/otb/viewer.html`, ~4.8 MB), fills the curator's reference OTV page (a D3 collapsible tree with isA and isA + instanceOf views, search, zoom, rotation, spacing controls, draggable tooltips and Leaflet tooltip maps for lat/long attributes; D3 and Leaflet load from CDNs) with data built from the model: all 21 concepts as tree nodes with their isA hierarchy, and in the combined view the COMPLETE object inventory (all 7574 objects), each object grouped under exactly its own concept in model order (the reference's `skos:example` grouping could list one object under an ancestor concept too; with the full inventory that would double every such node; the example closure itself stays in the RDF and `validate-otb` still pins it). Object tooltips carry label/prefLabel (the model label, not the fragment-id fallback of the reference tool), the note, literal attributes (repeated attributes get language-suffixed keys instead of dropping values), relation targets joined with ", ", and, for Place objects only, viewer-layer latitude/longitude from the curated `PLACE_COORDS` table, which activates the shell's Leaflet map without touching the RDF model. Objects with a curated Commons depiction additionally carry viewer-layer `depiction` (the shell renders it as the tooltip image) and `image credit (<license>)` (an https value the shell renders as a clickable tooltip-link to the Commons file page, with the license short name in the key so CC images show their license in the tooltip) attributes from the same `depictions.ts` table the proper name dictionary uses; again viewer-only, no RDF change. Concept tooltips carry the bracketed `conceptName`, axiomatized relations declared on the concept (alphabetical, ranges joined), and `attribute`/`denotedByTerm` lines that join multiple values with ", " instead of keeping only the last as the reference tool does. The shell is the reference page with exactly one documented deviation (the combined view starts collapsed like the isA view: the reference auto-expanded every object, fine for its 47 examples, unusable for 7574; clicking a concept unfolds its instances; a known consequence is that the shell's search only matches rendered nodes, so an object is findable via search only after its concept is expanded, or via Expand all) and only the title, the stats line and the data blob interpolated; beyond that `viewer-template.ts` is generated, not hand-edited; `<` is escaped to `\u003c` in the JSON and the smoke test's OTB drift group applies the same positive-controls-then-byte-equality contract, plus a `["Text",[` completeness control (the per-document Text objects were never part of the old example preload). The verbatim TEDI title "DiogenesLaertius" is kept for fidelity on the Overview page; `exportDate` is a DD/MM/YYYY string and must be rendered raw, never through `new Date(...)`
- **Terminology frontend** (`artifacts/laertius/src/pages/terminology/`, served at `/terminology` inside the main app): the former standalone Ontoterminology app merged into the laertius frontend as a nav section with sub-tabs (`components/terminology-nav.tsx`). Pages: Overview (metadata + inventory breakdown + RDF download + Term Dictionary link), Concepts (signatures + denoting terms), Objects (searchable browser with category/concept filters), Object detail (proper names, in/outbound relations, attributes, assertions; `cts` literals render a "Read this passage" link to the matching `/section/:id`), Proper Names (bilingual table with language filter), About the Model (the OTV/TEDI model explained). Cross-links the other way: `/api/annotations/entities` enriches entries with `otbObjectId` (exact-label match within kind-compatible categories, unique matches only, never guessed; `otb-entity-links.ts`), surfaced as a "Terminology entry" link on the Index page and the entity panel. The model also acts as a semantic layer at the point of reading: the Section page's entity panel opens with a "Terminological record" strip. Entities with an `otbObjectId` show their concept isA-chain, the concept's definition, Greek/English designations and the object note (fetched from `/api/otb`); Greek term tags show the doctrine concepts the term denotes via the optional `denotedConcepts` field on term entries (`doctrineConceptsForTerm` in `otb-entity-links.ts`, the same claims-layer pairing `lod.ts` emits as `otv:denotedConcept`, so the panel and the published RDF cannot disagree; the doctrine list is corpus-global, not context-sensitive, mirroring the model). The IONOS smoke test fingerprints every entry's `[label, kind, denotedConcepts]` row against the source derivation with positive controls on both sides. In the IONOS bundle the old `/ontoterminology/*` URLs 301-redirect to `/terminology/*` (one-to-one path suffixes, pinned by the smoke test). Favicon and opengraph image derive from the LAERTIUS wordmark; no platform branding, no em dashes, per project rules. The IONOS bundle smoke test keeps a dedicated OTB drift group (pins concept/category counts, positive ABox counts, RDF attachment header and XML well-formedness)

## Sources Index

- **Sources index** (`sources-index.ts`, `source-mentions.ts`): 529 workbook rows -> 252 authorities after label canonicalization; unknown authorities minted as `lo:Source`; one `lo:SourceCitation` per row with CTS URNs (5 refs pinned outside the Perseus text). **Source mentions**: opted-in minted authorities get section-scoped English tags; auto surface generation for those labels is suppressed in BOTH languages so minted authorities never knock out other bearers' tags. The workbook's extra Personal_Names sheets are deliberately NOT ingested (machine-generated links proven wrong; user: never use its IDs)

## External Identifiers

- **External identifiers**: Wikidata QIDs, VIAF/Britannica/DBpedia/InPhO, Philosophy Pages (38), Pleiades ids (all 171 places) - all fetched/verified at curation time, runtime stays offline. Policy: **never guess a homonym**; work QIDs verified via Wikidata P50 against the author

## Chapter Subjects

- **Chapter subjects** (`chapter-subjects.ts`): the 82 subjects of the Lives are classed by book: Book 1's eleven sages are `lo:Sage`, Books 2-10's 71 subjects are `lo:Philosopher`, Thales alone carries BOTH (curated `DUAL_CLASSIFIED_SAGES`, justified by his doxai and D.L. 1.13/1.27; serializers throw if a dual name isn't a Book 1 node), all share superclass `lo:ChapterSubject` (subClassOf foaf:Person). Ontology domain/range that said `lo:Philosopher` now says `lo:ChapterSubject` (prevents RDFS-entailing sages into Philosopher via succession edges). Each Life is also a `lo:Chapter` node (`/chapter/{book}.{chapter}`) with `lo:hasMainSubject`/`lo:inBook`/`lo:chapterNumber`, a bijection onto the subjects, per-book distribution 11/17/1/10/6/9/7/8/12/1 pinned by `validate-lod` (also pins 82/72/11 and dual={Thales}). Sages keep otv:instanceOf concept/sage (Thales both concepts), same URIs, same `lo:PhilosopherRole` role, and the gazetteer maps `lo:Sage` to kind philosopher, so tagging pins are untouched; chapter nodes have no kind and are never tagged

## Ontologies

- **Person ontology** (`person-ontology.ts`): `lo:hasRole` -> 14 `lo:Role` INDIVIDUALS (deliberately not classes - gazetteer kind detection reads node classes, annotation pins stay untouched) covering all 359 person-like nodes; `[]` = curated statement of ignorance; lod.ts throws on missing or dangling labels
- **Place ontology** (`place-ontology.ts`): closed type union on all `lo:Place` nodes (types become subclasses, every node keeps `a lo:Place`); `PLACE_LOCATED_IN` one-level containment between existing labels only; `lo:locatedIn` deliberately not transitive (chain with SPARQL `lo:locatedIn+`); labels are join keys - never touch them
- **Work ontology** (`work-ontology.ts`): all 847 works carry curated facets - form, 24-value topic, `philosophical`, survival (**lost is the default**: 748/20/72), composition century (negative = BCE); explicit `null` = curated ignorance; label-to-node bijection enforced; facets are individuals, not classes

## Map Data

- **Map data** (`place-coords.ts`, `place-mentions.ts`, `map.ts`): curated coordinates for 171 places (64 claim places + 106 mention-only, each guaranteed a text tag); mention places become `lo:Place` nodes, auto-feeding the tagging layers. Itineraries: per-philosopher journeys from located claims in narrative order (birth -> residences/travels -> death), 2 or more distinct places to qualify (26)

## Product Pages

- **Ask** (`/`): ranked cited passages + key findings — generative (cited LLM synthesis) when an OpenAI-compatible endpoint is configured, extractive otherwise; biography questions add claim/verse/saying answer cards (philosopher-gated via the KG)
- **Search** (`/search`): hybrid/sparse/dense mode toggle
- **Browse** (`/browse`): corpus browser
- **Section** (`/section/:id`): bilingual text, annotated-text highlights with entity panel, claims panel, LOD downloads
- **Graph** (`/graph`): d3-force network + succession tree (`?view=tree`, `?p=`); Hicks `book.section` refs resolve subject-aware for claims (the claim's own chapter wins on the 6 ambiguous keys); refs without a subject fall back to first-match. Tree placement: first teacherOf wins as parent, extra teachers dashed; a philosopher with no reported teacher is anchored under their first-listed `influenced` source with a dotted link (Epicurus via Democritus 10.2; also Empedocles/Hippasus/Philolaus/Archytas, Monimus/Menippus, Anaxarchus, Carneades), all influence edges between placed nodes render dotted; the remaining teacherless names stay in the "Outside the successions" pills (spouseOf never anchors, so Hipparchia stays a pill). The 34 school members (Garden, Sceptics, later Academy) render as satellite nodes (optional `associates` on `/api/graph`, built from school-members.ts, anchor derived via founderOf; deliberately NOT KG nodes - that would double-mint their LOD URIs); associates with a cited teacher (optional `teacher`/`teacherAsserted` from succession-links.ts, asserted link wins) hang from that teacher so the Sceptic succession of 9.116 renders as a chain, roster-only members orbit the founder; hedged members get a dashed dot + "hedged" badge, hedged teacher legs (the disputed 9.115 list) get the sparser dash + "reported" badge; associates use a lightweight side panel (pupil-of / taught lines, note + ref link), never ClaimsPanel (`/api/claims/:name` 404s for non-KG names); KG nodes with succession pupils (Timon, Lacydes) list them under "Pupils in the succession". Hegesinus -> Carneades (4.60) exists in LOD but is deliberately not a satellite leg (Carneades is a KG node; he stays linked via the Lacydes influence edge). Legend movement chips are clickable filters (toggle, multi-select, re-click or "show all" to clear): non-matching nodes and edges dim, satellites filter by their movement, filter composes with node selection and resets on same-page nav; `run e2e-legend-filter` is the live-browser check (same setup as e2e-nav-reset)
- **Doxography** (`/doxography`): searchable, filterable collections for Verses, Sayings, Anecdotes, Letters, and Doxai, all linking into sections; verses have a Poet filter + poets index (`?author=`)
- **Testaments** (`/testaments`): the six wills with cast lists and key provisions
- **Timeline** (`/timeline`): chronology bars for the 41 philosophers dateable from D.L.'s own reckonings (`timeline.ts` - years parsed ONLY from the claims' own "(N BCE)" glosses, negative = BCE; floruit glosses inside death notices never set the death year; missing endpoints derived from stated ages <= 110 and flagged approximate/hollow); movement-colored, expandable per-claim list linking to sections. `RELATIVE_DATED_MEMBERS` in timeline.ts adds Metrodorus (10.23: died age 53, seven years before Epicurus -> -277/-330, both approximate, resolved at runtime from Epicurus' computed death year); the other Garden members carry no date info in D.L. and stay off deliberately
- **Index** (`/entities`): all 753 tagged names and terms, faceted, deep-linkable (`?entity=`). The filter is a plain substring match over label and altTitle; when it matches nothing and the typed text is 3+ characters, a near-miss fallback offers "closest names" (any label/altTitle word within edit distance 2, or sharing a 4+ letter prefix, diacritics stripped on both sides), so a reader arriving from the Graph page's unknown-name notice with a spelling like "Zenon" still gets a lead instead of a dead end (pinned live by `e2e-graph-unknown-name` scenario 4)
- **About** (`/about`, footer-linked): detailed project description - text sources, retrieval, curated layers (live counts from `/api/corpus/stats`, incl. `totalDoxai`), LOD, method, licensing
- **Map** (`/map`): Leaflet + OSM (no key); 171 places / 119 events / 843 mention sections; side panel with cited events (rival death accounts get source badges) and passage links; life journeys (`?journey=`) with numbered stops, dashed legs for hedged accounts, never drawn between rival accounts of the same event; a "Show names" toggle in the legend row swaps hover tooltips for permanent name labels on every visible marker (labels are unbound before markers are removed on redraw, so a legend filter never leaves orphaned labels)
