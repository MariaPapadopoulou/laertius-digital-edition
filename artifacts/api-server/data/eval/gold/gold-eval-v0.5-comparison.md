## Reading

- Dense retrieval is the dominant component: it alone recovers most of the
  hybrid system's quality (recall@10 69.4% vs 71.4%; MRR 0.425 vs 0.459).
- Sparse BM25 lags far behind on every answerable metric (MRR 0.319,
  recall@10 48.4%), consistent with the gold questions being natural-language
  paraphrases rather than keyword-heavy queries.
- Hybrid fusion does help on answerable topics — it beats both components on
  all four metrics, adding +2.0pp recall@10 and +0.034 MRR over dense alone.
- On abstention-evidence surfacing, dense alone actually beats the original
  equal-weight hybrid (5 vs 4 false-premise evidence hits, 2 vs 0
  homonym-roster hits): equal-weight RRF with the BM25 ranking dilutes the
  contradicting / roster passages that dense retrieval finds.
- The tuned fusion (weighted RRF: denseWeight=1, sparseWeight=0.3, rrfK=20,
  KG boost rescaled to the same relative strength) fixes that trade-off. It
  beats the original hybrid on every answerable metric (+10.4pp recall@10,
  +0.047 MRR) AND matches dense-only on both abstention-evidence subtypes
  (5 false-premise, 2 homonym-roster hits). Selected from a 55-variant sweep
  over sparse weight × rrfK × KG-boost scale; see
  gold-eval-v0.5-fusion-tuning.md for the full grid. These parameters are now
  the production defaults (DEFAULT_FUSION_PARAMS in api-server rag.ts).
